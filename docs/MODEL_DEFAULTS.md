# 模型与思考默认值

客户端首次升级到包含 `terra-xhigh-upgrade-v1` 迁移的版本时，把每条已有连接的默认选择设置为 `gpt-6.1-terra` / `xhigh`。界面沿用现有“极高”文案，不改变模型选择器样式。

迁移与连接对应的“首次选择待确认”标记一同保存到本机。网络未连接、模型目录尚未返回、退出或重启 App，都不会消耗这个标记。待确认期间，恢复旧聊天返回的模型/思考设置也不会覆盖该选择。首次新回合发送被服务器接受，或用户主动选择模型/思考后，清除此连接标记；之后不再强制重置。向进行中的回合追加消息不能更换模型，因此不会消耗标记。

用户主动选择的模型、思考程度成对保存在设备私有 `model-defaults-v1` preferences。键包含连接 ID、主机、端口、登录用户、主机指纹、算法和 CLI 路径的哈希。同一服务器的两条连接仍有不同的偏好；不同手机也不共享本机偏好。客户端不写服务器全局 `config.toml`，不会修改其他用户的新聊天默认设置。

切换本机连接 ID 时，仓库也明确清空会话缓存；即使两条连接的主机和 SSH 用户名相同，也不复用前一条连接的聊天、模型目录或待发送草稿。普通同连接断线恢复保持既有恢复机制。

普通使用时，打开旧聊天显示该聊天设置，但不会保存成新聊天默认。回到主页、新建聊天、切换连接时恢复自己的默认选择。服务端模型列表仅用于确认模型及思考选项是否支持，不会用目录中的 `isDefault` 或低思考覆盖 Terra / 极高。若其他服务器没有该模型，则临时选择目录中可用的模型，不覆盖本机已保存选择。

验证重点：升级前保存其他模型、升级后未连接即退出再打开、模型目录和旧聊天响应的两种先后顺序、首次发送失败重试、用户主动选择后重启、两条相同主机但不同连接 ID 的偏好隔离。涉及服务器权限的聊天隔离另由服务端用户空间保证，本机偏好隔离不替代服务端权限。
