# 连接自己的 Codex

本 App 可以连接你自己的云服务器或局域网电脑。GitHub Releases 的公开 APK 不绑定作者的服务器，也不需要作者的激活邀请。模型认证、模型提供方和聊天历史由你连接的服务器管理。

## 先准备服务器

1. 安装、配置好 Codex CLI，并确保目标 SSH 用户在服务器终端中能正常使用它。本项目已验证 Codex CLI 0.169.0；其他版本需要兼容所用 App Server 协议，并支持 `codex app-server daemon start` 和 `codex app-server proxy`。
2. 开启 SSH，允许该用户通过私钥或密码认证、执行命令。图片、目录浏览、附件与文件下载还需要启用 SFTP。
3. 确保手机可以访问 SSH 地址和端口。云服务器使用可达的域名/IP；局域网电脑使用其局域网 IP，手机需处于可达网络。外出访问局域网电脑需要另外提供 VPN 或受控的网络入口，App 不会自动穿透 NAT。
4. 在可信的服务器终端确认 Codex 可执行文件位置，例如运行 `command -v codex`。App 默认 `~/.local/bin/codex`，安装在别处时需要修改。

App 使用 SSH 启动或连接后台 App Server，无需额外开放一个 Codex HTTP 端口。模型 API Key 或 Codex 登录状态配置在服务器上，不是在手机的 SSH 密码栏中填写。

## 在 App 添加连接

进入“Codex → 添加连接”或“设置”，按实际服务器填写：

| 字段 | 填写内容 |
| --- | --- |
| 显示名称 | 任意方便辨认的名字 |
| 服务器地址 | SSH 域名或 IP，例如 `192.168.1.100`；不加 `https://`，端口单独填写 |
| 用户名 | 服务器的 SSH 登录用户 |
| 端口 | SSH 端口，默认 `22` |
| 主机指纹 | 可信渠道取得的服务器主机公钥 `SHA256:...` 指纹 |
| 身份验证 | 导入客户端 SSH 私钥；若私钥有口令一并填写，或者选择密码认证 |
| 高级设置：Codex 路径 | 服务器上的真实可执行文件位置 |
| 高级设置：主机密钥算法 | 与上面的服务器主机指纹对应的算法，默认 `ecdsa-sha2-nistp256` |

主机指纹用于验证服务器身份，和你登录用的客户端私钥不是同一个概念。例如，在可信的 Linux 服务器终端查询其 ECDSA 主机公钥：

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub -E sha256
```

只有服务器确实使用该公钥、算法为 `ecdsa-sha2-nistp256` 时才填这组值。使用其他主机密钥时，填写对应公钥指纹及算法；不能把别的算法指纹配给默认算法。不要使用未经独立核对的网络扫描结果代替服务器身份确认。

保存并连接后，可选择项目目录、打开聊天或新建聊天。可选模型和思考档位来自服务器；服务器没有配置相应模型时，下载 App 不会自动获得模型访问权限。新聊天优先使用 Terra / 极高默认，实际可用性仍取决于服务器模型目录。

## 网络、系统与账户边界

- 填的是 SSH 地址，不是模型 API、ChatGPT 网页、Codex HTTP/WebSocket 地址。`127.0.0.1` 在手机上指手机自身，不能用它表示你的电脑。
- 当前远程启动命令使用 POSIX shell；Linux 是已验证的服务器环境。原生 Windows shell 不属于已验证环境。
- 当前表单支持私钥及密码认证，不提供交互式 MFA 或 ProxyJump 跳板配置。
- 同一服务器用户和同一 Codex 数据目录通常共享聊天。要让多个人的聊天分开，需要服务器侧隔离用户或 Codex 数据目录，不能仅靠手机里的显示名称区分。
- 手机凭据由 Android Keystore 加密保护。关闭手机连接不会停止服务器的后台 App Server。

## 公开 APK 与自行编译

从本仓库 **Releases** 下载的 APK，由 GitHub Actions 使用 `CODEX_MOBILE_PUBLIC_RELEASE=1` 构建，仅通过本仓库 GitHub Releases 检查更新，不包含私人更新地址或首装邀请。

自行编译时，不设置该变量默认使用 SSH 更新通道，读取的是你自己配置的 SSH 服务器，而不是作者的服务器。若需要 GitHub 更新源，需显式设置 `CODEX_MOBILE_PUBLIC_RELEASE=1`，且不要提供任何 bootstrap/test 环境变量。

自行签名与仓库正式签名不同，Android 不能将二者直接覆盖安装，App 也会拒绝签名不匹配的更新。希望持续使用仓库自动更新的普通用户，直接安装 Releases APK 即可。
