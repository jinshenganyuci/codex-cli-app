# 免配置首装与共同更新

免配置首装包用于把指定手机接入现有 Codex 账号。使用者会看到并能操作该账号的聊天、项目和文件；它不创建独立聊天空间。服务器继续使用原有模型配置，客户端不包含模型提供方密钥。

## 首次连接

专用首装包携带一次性激活邀请和已核验的公网 SSH 地址、主机指纹。手机首次运行时生成自己的 SSH 密钥，将私钥用 Android Keystore 加密保存，再通过受限激活账号注册公钥。专用包不携带现有账号或其他设备的 SSH 私钥。

每份邀请只绑定一个公钥。同一手机使用已保存的公钥重试可恢复中断的激活；另一公钥不能重复使用这份邀请。成功后，连接和凭据写入现有 `ConnectionStore`，应用使用普通连接流程。已有连接的安装不会被首装邀请覆盖。

0.2.11 起，尚未建立连接的手机在旧邀请激活失败后，可以直接覆盖安装携带新邀请的包。客户端核对邀请已变化后清理未完成的旧激活记录；同一邀请重试保留原密钥，同一邀请的主动取消继续有效。已有连接、已完成激活以及删除已完成连接后的终止状态都不会被重置。旧版在生成待激活记录之前就取消、且没有保存邀请标识的情况，继续保留取消状态。

专用 APK 本身含有可用于首次激活的授权信息，只私下交付给指定使用者。普通更新 APK、Git 仓库、源码 ZIP 和统一更新目录均不包含邀请材料。卸载应用或清除应用数据会丢失本机凭据，不能依靠已消费的邀请重新注册；这时需要重新签发邀请。覆盖安装更新会保留凭据。

## 私有构建输入

在 Debian 编译机以 `CODEX_MOBILE_BOOTSTRAP_FILE` 指向源码目录之外、访问权限受限的绝对 JSON 路径。该文件只作为私有构建输入，构建时生成 APK 的 `assets/codex-bootstrap.json`，不得复制到 `app/src/main/assets` 或其他受 Git 跟踪的目录。

未设置该环境变量时构建普通版本，生成目录中的旧邀请文件必须清除或隔离；从私有构建切回普通构建后，检查最终 APK 不含 `assets/codex-bootstrap.json`。源码归档应从明确的源码文件清单生成，排除 `work/`、`outputs/`、构建输出及所有私有配置，不能直接打包整个工作目录。

私有首装包和普通版本保持相同包名 `com.nanci.codexremote`、原有正式签名以及兼容的连接存储。专用包单独保存和交付，不放入统一更新目录。`scripts/publish-release.py` 在读取包内容时会拒绝含 `assets/codex-bootstrap.json` 的 APK。

## 后续更新

统一更新通道始终发布无邀请文件的普通正式 APK。新版本的 `versionCode` 必须高于手机已安装版本，包名与签名必须匹配。专用首装包完成激活后，普通版本覆盖安装会继续使用手机保存的连接，后续无需重新填写服务器地址或导入密钥。

更新检查与下载沿用独立 SSH/SFTP 通道及现有更新目录，不依赖 App Server 启动成功。下载后仍执行包名、版本、大小、SHA-256 和签名校验，安装由用户在 Android 系统界面确认。

## 验证范围

交付前应分别验证：空数据首次激活、断网后的同公钥重试、其他公钥拒绝、已有连接不被覆盖，以及专用首装包升级为普通版本后仍可连接。还需核对公网更新索引与 APK、普通 APK 和源码归档不含邀请、专用交付包的版本与校验和。实际执行记录与产物路径随该次交付归档，本说明不代替测试结果。
